# Retrieval evaluation

Run `npm run evaluate:retrieval` with local Ollama and `all-minilm` available. The script embeds four synthetic documents and four questions, ranks the documents by cosine similarity, reports each expected document's rank, top-1 count, mean reciprocal rank and elapsed time, and exits nonzero if any expected document is not ranked first. Override the service/model with `OLLAMA_URL` and `OLLAMA_EMBED_MODEL`.

On 2026-11-22, the local `all-minilm` model ranked the expected document first for all 4 of 4 synthetic questions (mean reciprocal rank 1.0; embedding and ranking elapsed time 358 ms in that run). This is a narrow smoke test, not an estimate of accuracy, production latency, citation correctness or unsupported-answer rate. It does not exercise PDF extraction, chunking, multi-user authorization, the API, or answer generation. The separate integration test exercises some of those paths, but is also not a quality benchmark.

Before treating the application as production-ready, add diverse real and adversarial documents, ambiguous and unanswerable questions, citation page ground truth, repeated runs and latency distributions. Review generated answers and citations independently; do not infer unsupported-answer rate from retrieval scores.

## End-to-end local-model smoke test

Start **dedicated, disposable** MongoDB and Redis services. Set `TEST_MONGODB_URI` and `TEST_REDIS_URL` to those instances, keep Ollama running with `qwen2.5:3b` and `all-minilm`, then run `npm run evaluate:rag`. Optionally set `TEST_OLLAMA_URL` and `EVAL_REPORT=/absolute/path/to/report.json`. The script launches an isolated API and worker, creates a fictional three-page PDF and a text note, uploads those plus a small Word DOCX fixture through the API, waits for embeddings, asks twelve questions, and generates a summary, flashcards and a quiz. It creates test accounts and queue entries, so never point it at user data.

On 2026-11-22, one final real-model run passed 10/10 **narrow heuristic checks**: six answerable PDF questions, two missing-information questions, one simple instruction-in-document case and one answer spanning both documents. The summary, three flashcards and three quiz questions in that run matched the visible fictional facts on manual review. The chat source links pointed to the expected pages; some answers had no model-written citation and were correctly labeled as **retrieved sources** instead. These checks do not prove that every claim is supported by its linked source.

Earlier runs exposed a fabricated citation number, a flashcard that swapped backup and deletion dates, a quiz with no correct date in its options, and a quiz that treated a backup deadline as the time of storage. The citation filter now removes references to sources outside the retrieved set. Flashcards receive a second, fallible model check. Quiz questions receive that check plus deterministic date consistency and nearby-sentence checks; questions that fail are omitted and counted. The final run did not reproduce those errors, and targeted unit tests cover the two quiz date mistakes. These filters are conservative, can still miss subtle errors, and increase response time. The second model check alone accepted a known wrong quiz answer during a direct test, so it must not be treated as a guarantee.

The end-to-end run used the API rather than browser automation; browser-control access was unavailable in this session. It did not assess complex or large DOCX files, OCR, real-world document diversity, long documents beyond the first five study chunks, repeated statistical accuracy, latency under load, or independent claim-level citation verification. Review AI output against the source before relying on it.

On 2026-11-22, a later isolated run with the new DOCX path passed 11/11 narrow chat heuristics. The Word fixture was uploaded, extracted in the worker, embedded, answered with the expected name and source, and served as a downloadable DOCX. The run also returned a correct summary, three flashcards and three quiz questions on manual review. Earlier runs in this change caught duplicate quiz options, mismatched distractor types and a flashcard that confused backup and deletion dates; the filters now reject those observed cases and retry quiz generation once if no acceptable question remains. This remains a synthetic smoke test. The source label for Word is document-level; its internal page value of 1 is not a rendered Word page number.

The latest isolated run passed 12/12 narrow chat checks, including a formatting follow-up. It produced a summary, three flashcards, and two quiz questions; one generated quiz question was omitted by the source filter. Batch fact checking reduces the normal flashcard and quiz verification to one model call per set, with individual checks as a fallback for malformed batch output. A separate stub-model integration run passed upload signature and size validation, duplicate rejection, worker processing and retry, owner isolation, refresh rotation, and deletion. These runs used the API and component tests, not a controlled live browser tab.
