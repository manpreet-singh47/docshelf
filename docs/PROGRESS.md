# Progress and limitations

## Implemented in source

- Responsive landing page, overview, document library, semantic search, AI workspace, collections, study studio with summaries and flashcards, usage and conversation history, sign-in/sign-up, theme switch, keyboard command palette, empty states, status badges and toasts.
- Account sign-in with short-lived access JWTs in memory and rotating, hashed refresh tokens in HttpOnly, SameSite cookies; origin checks for cookie-authenticated refresh and logout.
- Owner-filtered documents, previews, conversations, collections and quizzes; authenticated PDF/text preview, DOCX download, status polling and retry.
- Signature-checked 10 MB uploads, per-account 100 MB soft quota, unique duplicate index, random storage names and cleanup on enqueue failure.
- Separate BullMQ worker for page-aware PDF extraction, document-level DOCX extraction, chunking and local Ollama embeddings; local cosine retrieval, streamed grounded answers and links to cited pages; quiz JSON schema validation and storage.
- MongoDB/Redis Compose services, optional API/worker/web images, Nginx proxy, structured request logging, readiness endpoint, Redis-backed rate limiting, an optional fail-closed scanner hook and CI configuration.

## Important limitations

This is still a prototype, not production-grade. The API and worker have been tested with isolated MongoDB and Redis, both with a deterministic model stub and with the real Ollama embedding model. The real-model smoke test passes for Qwen chat; Docker remains unverified. The quota check is not atomic; uploads and PDF processing buffer files in memory. A malware scanner must be configured separately; resumable uploads, OCR, compression, automated orphan reconciliation, audit events and robust processing/deletion coordination remain outstanding. Local cosine retrieval scans a capped set of chunks; there is no dedicated indexed vector database. Chat source links distinguish model-cited excerpts from merely retrieved excerpts; neither independently verifies a claim. Quiz, summary and flashcard generation use only the first five chunks. Flashcards and quiz questions now pass fallible source filters, including specific date-consistency checks; summaries are not independently fact-checked. The filters may reject good content or accept bad content, and add local-model latency. The preview relies on the browser's PDF renderer; its page navigation support varies and the controls do not know the total page count.

Rate limits use Redis; Chat, quiz and study generation use a Redis-backed admission lease shared across API processes; API and worker embeddings use a separate shared lease. The pools may overlap. Access tokens are checked against their session on each request and are revoked on logout; this adds a database lookup to private requests. Refresh rotation is not coordinated across simultaneous browser tabs; a concurrent refresh can require sign-in again. Inference requests, file storage, queue operations and database mutations need stronger transactional and failure guarantees. The OpenAPI specification needs more detailed schemas and contract tests. There are no Prometheus metrics, full workspace membership, load balancer health-based routing, production secrets management, multi-replica deployment test, accessibility audit, comprehensive cross-user security coverage or a performance benchmark. Some UI areas and interactions remain minimal. The local deployment assumes a trusted machine; TLS and hardened external services are necessary before any public use.

## Verification

On 2026-11-21, typechecking, the production build, seven unit tests, and `npm audit --omit=dev --audit-level=high` passed (zero reported production vulnerabilities). An isolated integration run using MongoDB 7.0.16, Redis 7.4.2 and a deterministic model stub passed signup, signature and duplicate checks, upload, queued processing, streamed answer, cross-user isolation, refresh rotation, origin checks and deletion. The narrow browser layout was inspected and navigation to Study verified after fixing mobile navigation. This is not a complete accessibility or end-to-end UI audit.

On 2026-11-22 the upload and worker pipeline passed with Ollama all-minilm (384 dimensions), MongoDB and Redis. One small semantic smoke check ranked a relevant passage above an unrelated one. This is not an accuracy benchmark. The local runtime required CPU-only mode (`LLAMA_ARG_DEVICE=none`) because Metal allocation failed in the sandbox. On 2026-11-22 the real Qwen 2.5 3B Q4_K_M and all-minilm models passed a small end-to-end upload, TXT/PDF processing, streaming answer and page-2 citation smoke test with MongoDB and Redis. This is not an accuracy benchmark. Broader model quality, diverse PDFs, Docker deployment, multi-replica scaling, load and fault behavior remain unverified. The scanner hook is optional and is disabled unless explicitly configured; its tests cover an absent or failing scanner, not malware detection. Do not expose the service publicly until the remaining security and operational gaps are resolved.

On 2026-11-22, the TypeScript checks, production build and nine unit tests passed. Passwords are constrained to bcrypt’s 72-byte input limit, malformed resource identifiers return 404, and worker errors exposed to clients no longer include internal details.

The Qwen2.5 3B Instruct distribution used in this test is subject to the Qwen Research License, not Apache 2.0 as previously stated. Review the [model license](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct/blob/main/LICENSE) before redistribution or deployment. The PDF parser was replaced after a valid test PDF exposed an extraction failure; a two-page fixture now passes with a citation to page 2.

On 2026-11-22, added dedicated summary and flashcard generation, semantic search, basic usage counts, a landing page and PDF page controls. The summary/flashcard and semantic-search API paths passed smoke tests with the real local models, including owner isolation and derived-data cleanup. These checks use small fixtures, not a quality benchmark. Type checks and the production build passed. Browser layout and full interactive workflows for the new views have not been independently verified.

On 2026-11-22, reliability tests exercised a simulated model outage, automatic retry after a transient embedding failure, exhausted retries, owner-only manual retry, rejection of uploads above 10 MB, and the extracted-text limit. The worker now reports queued during automatic retries, reports a final failure only after retries are exhausted, and does not retry known extraction-limit failures. The API and worker handle shutdown signals. PDF processing is limited to 500 pages and 1,000,000 extracted characters. These limits reduce resource exposure but do not replace isolated parsing or eliminate PDF decompression risks. Malformed embedding responses and invalid chunk sizes are rejected. Type checking, the production build, 12 unit tests and the simulated-failure integration run passed; the production dependency audit reported no vulnerabilities. Shutdown under a long-running job and queue outage recovery are not yet end-to-end tested.

On 2026-11-22, added immediate access-token revocation on logout, stable refresh-session rotation, strict HS256 verification and an active-session check for private requests. Redis-backed per-account limits now apply to upload and inference requests in addition to the IP limit. Structured security event logs cover sign-in, signup, logout and document upload/deletion without logging credentials or document contents. The logs are not a tamper-resistant audit trail. Session, replay, cross-user and per-account rate-limit integration checks use isolated services and a stub model. Refresh-token reuse detection across multiple browser tabs, joint capacity management across generation and embedding pools, scanner deployment, atomic quotas and an independent security review remain open.

On 2026-11-22, a Redis-backed lease replaced process-local concurrency for chat, quiz and study generation. An integration smoke test using two API processes, one Redis instance and a stub model confirmed that a second concurrent generation receives a busy response. Leases expire after the request deadline to avoid permanent locks after crashes. This is not a load-balancer, fault-tolerance or throughput test, and the generation lease does not cover search or worker embeddings; a separate embedding lease was subsequently added.

On 2026-11-22, API and worker embedding requests were moved behind a separate shared Redis lease with bounded waiting. A stub-model test confirmed serialization across two API processes and between an API process and a worker; the real-model integration smoke test also passed. A Node demonstration proxy distributed 20 requests evenly between two API processes and served 10 requests after one process was stopped. This is not a Docker/Nginx or throughput test. Docker and k6 were unavailable; a locally compiled Nginx could not start because the environment blocked a macOS system call. Compose health checks, local distribution tooling and a k6 script were added but not executed in Docker or k6. Health and readiness endpoints are no longer subject to the normal API rate limit; 130 health probes passed the integration smoke test.

On 2026-11-22, an OpenAPI 3.1 document was added and validated; a CI check verifies that declared controller routes are represented. It is not an automated response-contract test. A reproducible four-question synthetic retrieval smoke evaluation using the real all-minilm model returned the expected document at rank one for all four questions in one run; this is not a real-world accuracy or latency benchmark. Added a fictional demo document, walkthrough and case study. Screenshots, broader evaluation and deployment verification remain open.

On 2026-11-22, initial frontend tests were added for the landing page, overview, sign-in dialog and search navigation. Axe-core checks run in jsdom for the landing page, overview and sign-in dialog, with color contrast disabled. The sign-in dialog now has accessible dialog semantics, focus containment, Escape handling and focus restoration; navigation state follows browser history between the landing page and workspace. Five frontend tests and 12 backend tests pass, along with API documentation validation and the build. These checks do not replace real-browser, screen-reader, color-contrast or comprehensive accessibility testing; see ACCESSIBILITY.md.

On 2026-11-22, an isolated real-Ollama API and worker run ingested a fictional three-page PDF and text note, then exercised chat, a cross-document answer, one simple prompt-injection case, summary, flashcards and quiz. The final run passed 10/10 narrow chat heuristics and manual review of the generated study content. Earlier runs revealed a fabricated citation number and several study date errors. Invalid citation numbers are now filtered; source links distinguish model citations from retrieved context. Flashcards and quizzes receive fallible checks, with targeted date-consistency guards and omitted-item counts. Unit tests cover the observed quiz date errors. The independent model check accepted one known bad quiz answer in a direct test, so generated content still needs human review. The API was tested directly, not through browser automation. The final typecheck, 20 API tests, 5 frontend tests, build, OpenAPI check, stub integration run and production dependency audit passed; no production vulnerabilities were reported by npm audit. See [evaluation](EVALUATION.md).

On 2026-11-22, a frontend component-flow test was added for choosing a PDF, seeing it in the library, asking a question, receiving a streamed answer and opening its cited page. It uses mocked HTTP responses, so it verifies the React interaction path rather than a real browser or model. A separate live HTTP check through the Vite proxy reached the existing local API, uploaded a text fixture, obtained a correct page-1 answer from Ollama and deleted the fixture; its two synthetic accounts and conversation were then removed. The intended isolated API could not bind because port 4000 was already in use. Headless Chrome and Safari automation could not start in this environment, so a real browser click-through and visual check remain open. Two visible headings still said Cortex and were changed to DocShelf.

On 2026-11-22, DOCX upload, worker extraction and download were added with a Word archive preflight. A real-model isolated run uploaded a small DOCX and answered its known question, and passed 11/11 narrow chat heuristics across PDF, TXT and DOCX fixtures. The UI calls Word citations document-level sources instead of claiming rendered page numbers. Archive checks limit entries and expanded bytes, but the parser still buffers the input and this is not a hostile-document security certification. The same evaluation exposed duplicated quiz choices, mismatched option types and a swapped flashcard date; targeted filters and regression tests were added. One final run generated factually consistent study content. The running localhost dev server was found to cache an older Cortex module despite updated source; the frontend entry and app modules were renamed so a normal page refresh requests the current DocShelf module. The existing API process could not be restarted from this sandbox and may need a manual restart to serve new DOCX support.
